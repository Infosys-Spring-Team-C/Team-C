Diagnosis (BUG-016):
  frontend/api_compat.py imports `requests`, and the adapter tests import that module,
  but `requests` was only listed in frontend/requirements.txt. A developer who installed
  the declared test tooling therefore could not collect tests/test_frontend_compat.py.
  The working tree's existing virtual environments had `requests` installed for other
  reasons, which is why the defect only surfaced in a fresh environment.

Fix:
  requirements-dev.txt now pins requests==2.34.2 with a comment explaining that it is
  needed to import the adapter in tests and that the backend runtime does not use it.
